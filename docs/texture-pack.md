# Texture replacement trial (x2 and x4, Kokiri Forest)

Local, optional packs of enlarged textures (four variants), to judge before any full pack. Everything derived from the cartridge stays in git-ignored `out/`; nothing is published (the Pages build copies no pack).

## Hook

- `tools/tex/hash.ts`: name of a decoded texture = 64-bit hash (16 hex digits) of its size and its RGBA8 texels as the interpreter produced them (after the tile's format and palette), shared by the renderer and the tools.
- `web/tex-pack.ts`: fetches `/texpack/<variant>/index.json` (404 or anything not JSON: no pack) and `/texpack/<variant>/<hash>.png` on first sight of a hash. The variant is `localStorage['oot.texpack.variant']` (default `a`); `ootTexPack.pack.setVariant(name)` switches it at run time. `tools/tex/serve.ts` serves `out/texpack/` (or `OOT_TEXPACK_DIR`) from the dev and preview servers to loopback clients only, mapping only `<variant>/index.json` and `<variant>/<16 hex>.png`.
- `web/renderer.ts`: a replacement exactly 2 or 4 times the size of its texture is uploaded in its place; the tile's coordinates, origin, shift and mask periods are scaled by that factor in the uniforms, so the shader's wrap, mirror, clamp, filter mode, mip levels and anisotropy apply unchanged. Others stay original. Key **T** (or `localStorage['oot.texpack']='0'`) switches between original and pack; `globalThis.ootTexPack` is the handle the compare tool uses. With the pack off (or absent) the draw is the old path: same upload, scale 1.
- A texture whose pixels change every frame hashes differently each time and gets no entry: it stays original. `dump` reports them (see below).

## Tools (`npm run tex -- <command>`)

- `dump`: plays the scripted new game headless to Link's house under control (frame 19,000), loads Kokiri Forest (entrance 238, 3,000 video frames with A taps for the cutscene, then a stick walk), then the six interior entrances the forest's exit list names (626, 193, 201, 156, 1075, 1079; `docs/re/display-lists.md` section 9), 700 frames each. Writes every unique decoded texture to `out/texdump/<hash>.png`, `index.json` (size, tile format, wrap/mirror/clamp per axis, alpha kind, frames seen, scenes) and `report.json`. Churn rule: a group (size and tile format) is churning when it is drawn in at least 20 graphics tasks and has new pixels in at least half of them; its textures seen in at most 5 tasks are marked volatile and skipped.
- `upscale`: enlarges every non-volatile texture of at most 128 px a side seen in at least 3 tasks into four packs, `out/texpack/<variant>/`: **a** x2, 50% model + 50% bilinear; **b** x2, model only; **c** x4, model only; **d** x4, 75% model + 25% bilinear. Per texture: padding of 16 texels (wrap, mirror or clamp per axis, from the tiles that sampled it); colour under fully transparent texels bled from visible neighbours; the model enlarges the opaque colour picture; the result is cropped back and mixed with plain bilinear by the variant's share. **Alpha never goes through the model**: it is the padded alpha enlarged by plain bicubic (Catmull-Rom) filtering and left as a gradient, so the game's alpha compare (and the filter at the edge) meets the same kind of ramp as with the original and the silhouette keeps its place (an earlier version cut it at 128, which shrank cut-outs against the original's 32/255 test). Transparent texels then take the colour of their nearest visible neighbour (no halo). Gray textures stay gray. Each wrapping axis is checked against the plain bilinear enlargement of the same texture (seam ratio). `index.json` of a pack records model, file hashes, settings, texture memory (RGBA8 bytes, 4/3 of that with mips) and build time.
- `compare`: headless Chrome, game in Kokiri Forest from save state 1 (a copy of the saves folder), six places by held arrow keys; at each the frame is frozen and drawn by the page's renderer with the original textures, with each variant, and with the originals again (to check it returns to the same picture). Writes `out/tex-compare/view-N-*-<original|a|b|c|d>.png`, a `bush` and a `wall` close-up (1:1, 480x360, centred on the largest on-screen surface drawn with the texture kind) per variant, and `index.html`: a swipe slider per picture, two selectors (left and right) that pick the original or any variant, and a table of memory and times.

## Findings

- Texture memory (601 textures, RGBA8; 2.7 MiB as originals): a and b 10.8 MiB (4x), c and d 43.2 MiB (16x); with mip chains 14.4 and 57.5 MiB. Build time on this machine: x2 model 47 s and x4 model 60 s for the 601 textures (CPU, numpy), plus 5 s (x2) or 15 s (x4) of padding, blending, alpha, checks and PNG writing per variant.
- Some 32x32 textures (the forest's ground among them) are decoded from a tile taller than what the game loaded: the upper rows hold stale texture memory and change from one scene state to the next, so one ground texture has dozens of hashes that differ only in their upper half (`tools/tex/families.ts`; the rows are never sampled, the tile's origin is in the lower half). The hash covers the whole decoded picture, so a pack made from one run misses the variants that run did not see, and those draw as the original until the pack holds them. A stable name for these would need the interpreter to hash only the sampled rows (`runtime/gfx/`, outside this trial).
- Seams: variant a has none worse than plain bilinear; b 3, c 11, d 9 of 380 wrapping axes (the model's own sharpening at the seam, not padding).

## Model and settings used

Third-party model, run locally, weights not committed: `realesr-animevideov3-x2` from the official release `xinntao/Real-ESRGAN` v0.2.5.0, asset `realesrgan-ncnn-vulkan-20220424-windows.zip` (zip SHA-256 `abc02804e17982a3be33675e4d471e91ea374e65b70167abc09e31acb412802d`), extracted into `~/.zelda-oot-js/tools/realesrgan-ncnn-20220424/`. The x2 and x4 model files are read by `tools/tex/model_run.py` (numpy; Python 3.12 venv at `~/.zelda-oot-js/tools/venv` with `numpy` and `pillow`). Why not the release's own executable: its Vulkan build lost the device on the RTX 4060 Ti (`vkWaitForFences failed -4`), and the `ncnn` Python package returned different, partly garbage output on every run of this model; the numpy reader matches the clean ncnn output (mean difference 0.06/255) and is deterministic. This model is not a general-purpose one: it is a compact network for cartoon video; the release's x2 variant is its x4 network followed by a bicubic halving (end of its param file). At full strength (variant b) it draws ink-like outlines on bark and eyes; variant a mixes it 50/50 with bilinear.

Run: `npm run tex -- dump && npm run tex -- upscale && npm run tex -- compare`.
