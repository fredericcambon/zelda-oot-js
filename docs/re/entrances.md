# Entrances: what the table's records are, and how the Warp list names them (PAL 1.0)

Addresses are main-code-file RAM addresses unless stated (`gaps.md` and `saves.md` give the table and the save context). Reproduce the numbers with `OOT_ROM=<rom> npx tsx tools/assets/places-report.ts [--all]`.

## One arrival point has several records

- **The table.** 1556 records of 4 bytes at `0x800F7BF0` (`gaps.md`): byte 0 scene, byte 1 spawn, then a halfword of flags (bit `0x4000` lets the scene's title card be drawn, `title-cards.md`). 37 records name a scene past the 101 scene records and are not used.
- **Which record is used.** The play state's init (`0x8009AEA0`) loads the entrance index from `0x801183D0` (the save context's `+0`, `lw` at `0x8009B17C`) and the record `table[index + variant]` (`sll`/`addu` at `0x8009B268`-`0x8009B274`; `lb` of byte 0 and byte 1 at `0x8009B278`/`0x8009B27C`, passed to the scene loader `0x8009D63C` as scene and spawn). So a table index is the first of a run of records, and the game adds a variant to pick the record of the run.
- **The variant** is the word at `0x80119730` (save context `+0x1360`), set at `0x8009B0D8`-`0x8009B178`:
  - If the word at `+0x135C` is not 0, or the cutscene index at `+8` is `0xFFF0` or more (`0x8009B0E4`-`0x8009B0F8`): variant = 4 + (cutscene index & 0xF) (`0x8009B104`-`0x8009B114`). Records 4 and up of a run are cutscene set-ups.
  - Otherwise two words give 0 to 3: `+0x10` and `+4`. `+0x10` is 1 at night and 0 by day: the code at `0x8009B0AC`-`0x8009B0CC` compares the time of day (`+0xC`): `slti` against `0xC001` at `0x8009B0B0` and against 17749 (`0x4555`) at `0x8009B0B8`, so `+0x10` is 0 only while `0x4555 <= time < 0xC001`. With `+4` not 0 the variant is `+0x10` (0 or 1: `0x8009B118`-`0x8009B154`); with `+4` 0 it is 2 + `+0x10` (`0x8009B158`-`0x8009B178`).
  - Then two scenes override it (`0x8009B198`-`0x8009B268`): when the record at the index names scene `0x51` and `+4` is not 0, the variant is 1 only if three masks of a table at `0x800F6B50` (`+0x48`, `+0x4C`, `+0x50`) all match the word at `+0xA4`, else 0; when it names scene `0x55`, `+4` is 0 and the variant is below 4, the variant is 2, or 3 when bit `0x100` of the halfword at `+0xEDC` is set.
- **Observed** (`tools/headless/entrance-variant-rom.test.ts`, scripted new game, entrance 238 forced with the time of day written first): the variant word reads 1 for times `0x0000`, `0x4554`, `0xC001` and `0xFFFF`, and 0 for `0x4555`, `0x6AAB` and `0xC000`. So variants 0 and 1 are the day and night records. The new game has `+4` = 1. The word cannot be changed from outside: writing 0 to it, it read 1 again after the scene loaded (it is rewritten by the overlay of file 35 at `0x808496E8` from a byte of the play context), so what `+4` means (the variants 2 and 3, age is the obvious guess) is **not proven**: the list calls those records "variant 2" and "variant 3".
- **What differs between the records of a run.** Scene and spawn are the same (for example entries 238 to 241: scene 85, spawn 0); only the flags halfword differs (`0x4183`, `0x4102`, `0x4183`, `0x4102`). They are the same arrival point reached in four conditions.
- **Several runs for one spawn.** Other runs name the same scene and spawn (entry 521 and others also land at scene 85, spawn 0): they are other entrances (other exits of other scenes, cutscenes, events) to the same spot.

The Warp list therefore has one row per scene and spawn: 1519 valid records make **390 rows** in 101 scenes. A row has a button per record of its first run (day, night, variant 2, variant 3) and the rest under "more entries" (cutscene set-ups and other runs). A run starts where the scene or spawn changes or an exit list names a record; the run an exit list names comes first.

## Exit lists: where each arrival comes from

- Scene header command `0x13` (handler `0x800829D8`, table `0x800F6ED0`) stores the segment 2 pointer of its operand in the play context at `+0x11E04` (`sw` at `0x80082A14`).
- The code that takes an exit (overlay of file 35, `0x80837CDC`-`0x80837CF8`) reads the halfword at `list + 2 * (exit number - 1)` (`lh -2(t4)` at `0x80837CEC`) and stores it at `+0x11E1A` of the context, the next entrance index (`0x7FFF` is a special case, `0x80837D08`). So the list is the entrance indices the scene's exits lead to, by exit number.
- The list has no length. It is read from its pointer to the next segment 2 pointer of the header (the list is followed by other tables), dropping halfwords that are not entrance indices (1556 or more) and zeros at the end (padding). 100 of the 101 scenes have the command (scene 71 has none): 295 exits.
- An exit of scene A to a record that names scene B is a link A - B, and the record is where the arrival comes from. A row's "from" names the scenes whose lists name one of its records.

## Names

1. **Scenes with a title card (65 scenes): proven.** The card picture is the evidence. The English picture of each of the 57 card files was looked at and its text typed into `web/inspect/card-names.ts` (file table index to text; `npx tsx tools/assets/title-cards-report.ts` writes the pictures to `out/title-cards/`). Scenes sharing a card file share the text; the list tells them apart with a count, "Market (2)". File 937's card says "?" and is listed as "?".
2. **Scenes without a card (36): derived.** A scene is named "Off <name>" after the proven names of the scenes it is linked to (either direction), by breadth first search from the proven scenes: scenes linked to a proven scene first, then scenes linked to those, taking the proven names at the root; two names are shown, "Off A / B", more as "+n". What the place is (a house, a grotto, a shop, a boss room) is not known from the data and is not guessed. 35 scenes get a name this way; scene 71 has no link to any named scene and shows "Scene 0x47".
3. **Arrivals inside a scene.** A scene with one row is named after the scene. With several, the name is "<scene> - from <scene>" (the scenes whose exit lists name its records, two at most), or "<scene> - spawn <n>" when no exit list names it (141 rows: reached by cutscenes, actors or events). The scene's own label, and an arrival's own label, replace the names (marked "yours").

Coverage (390 rows): **311 rows have a proven text name** (their scene has a title card), **78 have a derived name**, **1 has neither** (scene 71, "Scene 0x47", 14 records). 249 rows are told apart by where they come from, 141 by spawn number only. 31 rows have one record, 287 have 4, 31 have more.
