# New game: the JPEG task, Link's house and the headless flow

Evidence from the PAL 1.0 ROM. Addresses are virtual; `npx tsx tools/analyze/disasm.ts code <addr>` lists the main code and `npx tsx tools/analyze/rsp.ts code 800e4b10 1000` lists the microcode below (offsets are RSP instruction-memory addresses).

## The type-4 task with the microcode at 0x800E4B10

The first trap after creating a file and starting the game was `RSP task of unknown type 4 (flags 0x0, ucode 0x800e4b10, data 0x8014f680+0x20, called from 0x800a37c0)`. The caller is the task scheduler: `0x800A37BC` calls `osSpTaskStartGo` (`0x800D01BC`).

- **Who builds it.** `0x8005B6E0` copies the 64-byte template at `0x800EF4C0` (`addiu t5,t5,-2880` at `0x8005B788`, copy loop `0x8005B7AC`-`0x8005B7DC`) into a scheduler record, sends it with `0x80001F80` (`osSendMesg`) and waits for completion with `0x800021A0` (`osRecvMesg`). The template holds type 4 (`+0`), the microcode `0x800E4B10` with size `0x1000` (`+0x10`, `+0x14`), its data `0x80112B70` with size `0x800` (`+0x18`, `+0x1C`) and a data size of `0x20` (`+0x34`); the code fills in the boot microcode (`+8`, `+0xC`, results of `0x800AD0E0` and `0x800AD0F0`) and the data pointer (`+0x30`, `0x8014F680` at run time).
- **Who uses it.** `0x8005B6E0` is called from the loop at `0x8005BDD4`-`0x8005BE58`, 75 times (`s6` runs 0 to 300 in steps of 4). Each pass calls `0x800CF5F0` to Huffman-decode four macroblocks into `0xC00` bytes at `s5 + 0x6C0` (`0x8005BDEC`), runs the task, then `0x8005B81C` copies 16 rows of 16 halfwords from each 768-byte macroblock into an image whose rows are 640 bytes apart (`0x8005B81C`-`0x8005B94C`), 20 macroblocks per row (`slti 20` at `0x8005BE30`): 300 macroblocks make 320x240 halfwords. The stream parser at `0x8005B9A0` skips to `0xFF` bytes and dispatches on the next byte minus `0xC0` through the table at `0x80105870`: the JPEG marker segments (start of frame, Huffman and quantisation tables, start of scan).
- **What the microcode reads.** The data block is 32 bytes (`+0` macroblock address, `+4` count, `+8` mode, `+0xC`/`+0x10`/`+0x14` three tables); `0x8005B6E0` stores physical addresses (`s5 + 0x6C0` and so on, with `0x80000000` added to the buffer pointer, which wraps). The microcode loads the block to `0x1E0` (`0x038`-`0x044`), the three tables to `0x60`, `0xE0`, `0x160` (`0x054`-`0x080`), and per macroblock DMAs `0x300` bytes in (mode above zero, `0x0A4`-`0x0AC`) and `0x200` bytes out. The tables are 64 halfwords copied from the stream by `0x800CF0E0` and the blocks are 64 halfwords in zigzag order written by `0x800CF818`.
- **What it computes.** Multiplies coefficients by the table (`vmudh`, `0x154`-`0x18C`), scatters to natural order (`ssv`, `0x23C`-`0x338`), runs an 8-point inverse DCT twice with the cosine constants stored at `0x80112B80`-`0x80112BBF` (`0x5A82`, `0x18F9`, `0x6A6E`, `0x8276`, `0x471D`, `0x30FC`, `0x89BE` are the cosines of multiples of pi/16 times 32768), then converts YCbCr to RGB with the multipliers `0x670A`, `0x5824`, `0xB6E3`, `0xC5E3` (1.4025, 0.3443, 0.7144 and 1.7731 once the integer part is added where the code adds the operand back, `0x64C`-`0x674`) and packs five-bit channels with alpha 1 (`0x6DC`-`0x738`, multipliers `0x800`, `0x40`, `0x2` and the OR of 1). The result overwrites the start of the macroblock.
- **Check.** The runtime implements this in `runtime/jpeg.c`. After the game starts, the 320x240 image it builds (RDRAM `0x80129E80`, ending where the task's work buffer begins) is a top-down picture of the treehouse interior: bed, table, door, rug.
- **Not implemented.** Mode zero (`0x5A0`-`0x75C`, two luma blocks per macroblock) is never used here; the runtime stops with a message if it meets it.

## Scene and Link

- The scene loader `0x8009D640(ctx, index)` stores the index at `ctx + 0xA4` (`sh a3,164(s0)`, `0x8009D6B0`) and the address of its 20-byte record in the table at `0x800F9440` at `ctx + 0x1242C` (`0x8009D6AC`). `ctx` is the word at `0x80112BE0`.
- Scene 52 is loaded when the new game starts and again after the opening: the narration at frame 4400 and the Navi dialogue at frame 16000 are in it, and its background is the treehouse. Between them the context holds scenes 81 (frame 7000) and 85 (frame 13500).
- Link's record: at `ctx + 0x1C30 + 8 * 2` the context holds `{count, head}` of a list of one actor; the head's first word is `0x000002FF` (id 0, category 2, room -1) and the three floats at `+0x24` are its world position. A second copy sits at `+0x08`; the camera holds its own copy (the pointer to Link at `0x801C6750`, the position at `0x801C6754`). The category index 2 and the offsets were found by comparing memory snapshots taken while the stick was idle and held: the triple does not change in idle frames and moves roughly 1.5 to 2 units per frame with the stick held, with `y` constant. It starts at (0, 0, 60) in the house.
- The camera of the house is fixed above the room, so "forward" on the stick moves Link towards +x, -z.

## Headless flow

`npm run headless -- --input tools/headless/newgame.input --frames 19300 --dump out/frames --dump-at 4400,16000,19000` plays the whole flow. The input file lists the controller state per frame (`<frame> <buttons> [x y]`) and `tap` lines that press a button periodically; the file explains its own steps. The opening takes about 19,000 frames: the game waits for A at several dialogue boxes, so A is tapped every 100 frames from frame 9400 to 18700. The headless test `plays a new game ...` runs it and checks the scene, the decoded background, Link's position and the frames.
